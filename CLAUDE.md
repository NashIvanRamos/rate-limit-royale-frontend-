# Development Workflow & Git Guidelines

## Step 1: Complete the Assigned Group of Tasks
- Work only on the current assigned group of tasks.
- Follow the project's documentation, architecture, and coding conventions.
- Ensure all tasks in the current group are completed before moving forward.

## Step 2: Validate the Implementation
- Run the relevant tests.
- Verify that the implementation works as expected.
- Fix any errors or regressions before proceeding.
- Do not push incomplete or unverified work.

## Step 3: Commit and Push to GitHub
- Review all modified and newly created files.
- Stage the relevant changes.
- Create a descriptive Git commit.
- Push the completed work to the GitHub repository.

## Step 4: Create a New Branch
- After successfully pushing the completed group of tasks, create a new branch for the next group.
- Use descriptive branch names that reflect the next task group.
- Ensure the new branch is based on the latest completed work.
- Switch to the newly created branch before starting the next group.

## Step 5: Proceed to the Next Group
- Begin the next group of tasks only after the previous group's changes have been successfully pushed.
- Maintain the same workflow for every subsequent group.
- Never skip validation, committing, or pushing.
- Never combine unrelated task groups into a single commit or branch.

## Step 6: Repeat
- Continue this process until all documented project milestones and tasks are completed.
